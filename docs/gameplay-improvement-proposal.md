# 明日方舟猜干员 · 玩法优化与新模式提案

> 状态：**方案调研稿（未改代码）**
> 范围：可玩性提升（维度可记忆性 / 大类分层 / 冷门输入门槛）+ 新模式
> 约束：保持防作弊架构（谜底与服务端数据永不下发、token 无状态）、保持 vanilla JS + CommonJS、数据继续由 `scripts/build_data.py` 生成。

---

## 0. 先说结论（TL;DR）

现有 12 维里，**战斗经验（76 个数值）、生日（365 个可能值）几乎无法靠玩家记忆参与**，是"纯盲猜 + 高低箭头"体验；**种族（45 值）、出身地（33 值）是扁平长尾列表**，含大量"未公开/未知/自称"噪音，没有大类可做排除推理；**冷门干员**则被"必须输入精确名"卡死。

数据调研结论：**Kengxxiao/ArknightsGameData 一个仓库就足以提供 10+ 个高可记忆新维度**（阵营、国家、干员编号、获得方式、限定标记、技能名、天赋名、特性、费用/再部署/阻挡数、基建技能、模组名），并支撑 5+ 个新模式（台词猜谜、技能猜谜、公开招募模拟、语音猜谜、剪影猜谜）。**不需要新引入重型依赖，把 12 维里最差的 3~4 维换掉/补强，再把输入门槛拆掉，可玩性会立刻质变。**

建议落地顺序：**P0 数据维度 + 外号输入 + 池子筛选 + 提示卡**（一周内见效）→ **台词猜干员 + 公开招募 + 每日挑战**（中期）→ 语音 / 剪影 / AI 提示助手（长期）。

## 2. 现有玩法的问题诊断（用真实数据量化）

对 `server-data/operators.json`（425 名干员）统计：

| 维度 | 离散值数 | 分布情况 | 问题 |
| --- | --- | --- | --- |
| 战斗经验 | **76 个数值**（0~76 稀疏分布） | 连续值，玩家对任何人的战斗经验都无记忆 | 只能靠"高/低"箭头盲猜，无成就感 |
| 生日 | 365 种可能（26 人 null） | 连续日期 | 同上；对大多数玩家是纯噪音 |
| 种族 | **45 值** | 前 6 名（菲林52/黎博利43/萨卡兹29…）覆盖约一半，长尾一堆 1~2 人的冷门 + "自称/未知/未公开/不明" 噪音（共 39+ 条非标准值） | **无大类分层**，无法"先粗后细"排除 |
| 出身地 | **33 值** | 头部 10 个地区覆盖大半，但含"汐斯塔（独立城邦）/泰拉东部某处灌木林/因经纪公司要求不公开/自称"等 1~2 人玩笑值 + "未公开 20/未知 17/不明 4" | 同上；且出身地≈国家，信息冗余 |
| 性别 | 7 值 | 女315/男104 + 未知/断罪/女士/自称雌性 | 玩笑值稀释信息 |
| 标签 tags | **131 种组合**（底层约 20 个标签） | 组合爆炸 | 组合式展示反而难记难推理 |
| hot 标记 | 331/425（78%） | 规则=星级≥5 | **几乎没有区分度**，不适合当池子筛选项 |

**三个核心痛点对应的根因：**

1. **"战斗经验、生日没印象"** → 连续型、无先验记忆锚点的维度占用 2 个格子；玩家参与感靠"方向箭头"而非"我知道"。
2. **"种族、出身地没有大类分层"** → 扁平长尾 + 玩笑/未知噪音；`exact/wrong` 反馈给不出"在哪个大类里"的中间态。
3. **"冷门干员叫不出来"** → 必须输入精确名（拼音联想只解决"会读"，不解决"记得住"）；全池 425 人出题，冷门占比高；`hot` 筛选规则失效。

## 3. 数据增强方案：新维度（全部服务端计算，防作弊不变）

原则：**新维度只下发"比较结果/提示"，永不下发谜底值**；都从 `character_table.json` 等源表生成，进 `server-data/operators.json`。

### P0 —— 高可记忆维度，替换/补强最差的几格（建议：战斗经验、生日、出身地、种族）

| 新维度 | 数据字段 | 比较语义 | 可记忆性理由 | 难度 |
| --- | --- | --- | --- | --- |
| **阵营 groupId** | `groupId`（罗德岛/企鹅物流/乌萨斯学生自治团/莱茵生命/龙门近卫局/喀兰贸易/深海猎人/使徒/格拉斯哥帮/岁…，约 20 类） | exact / wrong | 玩家对阵营如数家珍（"她是企鹅物流的"） | 低，最佳替代"出身地" |
| **国家 nationId** | `nationId`（乌萨斯/维多利亚/炎/萨尔贡/拉特兰/谢拉格/叙拉古/卡西米尔/莱塔尼亚/龙门/东国/伊比利亚/玻利瓦尔/哥伦比亚/雷姆必拓/卡兹戴尔/萨米/米诺斯/阿戈尔…） | exact / wrong | 大分类，与"出身地"形成**两级分层**（国家 → 具体地） | 低 |
| **干员编号 displayNumber** | `displayNumber`（如 `PL03`：前缀=阵营缩写 + 序号） | 前缀 exact/wrong + 序号 high/low | 老玩家记得"PL 是企鹅物流""XX 是第几个实装"；猜法独特有趣 | 中 |
| **获得方式 itemObtainApproach** | `itemObtainApproach`（公开招募/常规寻访/**限定寻访**/活动赠送/凭证交易所…） | exact / wrong | "谁是限定""谁活动送的"是玩家最熟的话题之一 | 低 |
| **是否限定** | `isLimited` | exact / wrong | 同上，热门谈资 | 极低 |
| **技能名（1/2/3 技）** | `skills[].skillName` | exact / wrong（或做成"猜技能"模式见 §5） | "真银斩""火山""过载模式"——玩家对技能名的记忆远强于生日 | 低~中 |

> 反作弊提示：技能名、编号等新数据只进服务端档案；`public/data/names.json` 继续只放 {n,p,i,hot}。

### P1 —— 中等可记忆性，作为加分维度或彩蛋

- **费用 / 再部署时间 / 阻挡数 / 攻击间隔**（`phases` 内，注意与潜能/精英化档位相关，需约定取精英二满潜或基础值并写死在文档里）：数值型，`high/low` 提示；玩家有"先锋低费、特种高再部署、重装阻挡 3"的直觉。
- **特性 traits**（"攻击造成法术伤害""攻击回复技力"…）：exact/wrong。
- **基建技能**（`baseSkills` / `building_data.json`）：老玩家基建梗（制造站效率、贸易站订单等），exact/wrong，适合当彩蛋维度。
- **种族大类（服务端归组表）**：不新增格子，而是给现有"种族"维增加**大类中间态**——把 45 个种族归入 6~8 个大系（哺乳/鸟/爬行·两栖/龙/精灵·阿戈尔/人类·机械/其他/未公开），猜错时返回"谜底属于 XX 大系"（`hint` 状态）。**这一条直接回应"没有大类分层"痛点，改动最小**。
- **模组名 / 皮肤名**：彩蛋级。

### P2 —— 轻量优化

- **数据清洗**：出身地/种族的"自称/断罪/女士/因经纪公司要求不公开/泰拉东部某处灌木林"等玩笑值归一化（如"未知/趣味"桶），减少噪音；新增 `special` 规则沿用现有斜纹渲染。
- **CV 声优**（需另行抓社区表）：可做彩蛋维度或台词模式的对赌条件。

## 4. 输入门槛方案（解决"冷门干员叫不出来"）

1. **外号/昵称归一化表**（最高性价比）：社区外号整理成 `public/data/aliases.json`（或服务端），输入"阿能/能天使/喷子"都命中能天使；"塞爹/塞雷娅""银老板/银灰""42/史尔特尔""水陈/假日威龙陈"等高频外号人工维护 200 条即可覆盖绝大多数场景。搜索与提交两个环节都做归一化。数据来源见 §1.2。
2. **池子筛选**（开局可选）：六星池 / 五星池 / 限定池 / 指定阵营池 / 指定国家池 / 编号区间池——玩家在自己熟悉的范围内玩，冷门比例下降；实现 = `poolFor()` 增加筛选参数（纯服务端，token 里带 pool 信息）。
3. **提示卡系统**：每局免费 1~2 张（或猜错 N 次赠送），用 P0 大类维度做提示，例如揭示"谜底属于：企鹅物流 / 拉特兰 / 六星 / 限定 / 技能2 是'过载模式'"之一。提示由服务端生成，不泄露谜底全名。
4. **剪影渐进揭示**（见 §5 模式）：立绘剪影随猜测次数逐步清晰，视觉记忆兜底。

## 5. 新模式提案（按"数据可得 × 趣味 × 成本"排序）

### 5.1 台词猜干员（Quote Mode）—— 建议第一个做，数据现成
- **文字版（零资源成本）**：`charword_table.json` 的台词文本（交谈1/信赖提升后交谈/作战中…）。服务端随机抽一句，前端展示，玩家猜干员。需清洗：台词常自带干员名（如"阿米娅，我们走"），用"干员名/代号"掩码替换为 `████`；可做**难度分级**（名台词 vs 普通台词）。
- **音频版（中期）**：播放语音片段猜干员；资源来自 Ark-Voice / HF 数据集 / prts.wiki 语音。注意资源 URL 不能带干员 id（用随机文件名或统一目录），否则等于泄露答案。
- **档案引用版**：用现有 `server-data/operator-archives.json` 的句子猜出自哪位干员的档案，考据党最爱。

### 5.2 技能/天赋猜谜（Skill Mode）
- 显示技能名 + 技能描述（数值打码），猜干员；或显示天赋名猜干员。数据：`skill_table.json` / `talent_table.json`。
- 变体：**技能图标猜干员**（`skill_table.iconId` + Aceship 图标资源），视觉向。

### 5.3 公开招募模拟（Recruitment Mode）
- 数据已基本在手（`tagList` 即公开招募标签；`gacha_table.json` 可确认招募池与稀有度）。
- 玩法 A：给一名干员，玩家选出能招募到他的 3 个标签（模拟公开招募，9 小时/3 小时 50 分等档位做辅助线索）。
- 玩法 B：随机给 5 个标签，玩家猜"能同时命中哪些干员"（多选）。
- 与现有 tags 维度深度联动，老玩家熟悉度高。

### 5.4 阵营/国家限定挑战（Faction Mode）
- 开局选定阵营/国家，谜底只从该池出（复用 §4 的池子筛选基础设施）；进阶：**两阶段玩法**——先猜阵营/国家（大类），再猜具体干员，天然实现"先粗后细"的分层推理，直接回应"没有大类分层"痛点。

### 5.5 每日挑战 + 连胜（Daily + Streak）
- 按日期做种子随机（服务端 `seed = hash(date)`），全体玩家同一谜底；本地记录连胜/最佳次数；配"X 次内完成"评级。低成本、高留存，适合打卡。

### 5.6 剪影猜干员（Silhouette）
- 用现有 `public/img/operators/` 立绘做剪影/马赛克，随猜测次数逐步清晰；纯前端 canvas 处理，零新数据。视觉记忆强，且与"输入名字"环节天然兼容（知道是谁但打不出名 = 外号表兜底）。

### 5.7 竞速/限时（Speed Mode）
- 每局总限时或每猜限时（如 20s），endless 变体；需要服务端 token 带时间戳/剩余时间（注意与防作弊的配合：计时放服务端判定）。

### 5.8 AI 提示助手（LLM Hint，长期）
- 服务端接入 LLM（或参考 prts-mcp 拿 wiki 数据）：玩家可请求一句"人类能懂的谜语式提示"，LLM 只基于服务端已知的已确认线索生成，不直接泄答案；可做成"百科竞猜"变体。实现成本高，作为远期彩蛋。

### 5.9 反向测验（Quiz Mode）
- "以下哪位是 XX"四选一（语音/技能/阵营/生日梗任选），碎片时间向，开发成本极低，可与 5.1/5.2 数据共用。

## 7. 反作弊与安全注意事项（沿用现有架构）

- 所有新数据只进 `server-data/operators.json`；接口只返回比较结果/提示，不返回谜底值；token 继续加密携带 `{name, mode, guesses, pool, …}`。
- 台词/语音/图标资源：前端可访问的资源一律不能带干员可识别 id（掩码、随机文件名、统一目录）；音频/图标走 CDN 时同样处理。
- 提示卡、每日种子、计时判定全部服务端完成。
- 数据规则变化后跑 `npm run build:data`（+ `build:archives`），两个生成文件需提交。
